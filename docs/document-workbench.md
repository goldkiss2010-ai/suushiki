# 複数数式の組版ワークベンチ

## 位置づけ

/document.html は、既存の /（単一数式の比較・計測）とは別の検証画面です。public/document-source.js が原文を数式・本文の項目に分解し、public/document-workbench.js が各数式を MathJax に測定させ、public/document-layout.js が Stone の測定・組版規則を使用して段落群を構成します。public/document-render.js はすでに決まった座標を描画するだけで、折り返しを再計算しません。

- 原文の \(...\) は非改行の数式項目です。同じ TeX の繰り返しも別の出現 ID になります。
- 改行、連続空行、原文に含まれる空白を区別します。原文を描画から再構成しません。
- 幅・位置は CSS px で報告します。MathJax の描画 SVG と同じ画面でベースラインを実測します。
- 数式の計測は TeX・サイズ・書体・画面倍率をキーに再利用します。ブラウザーのフォント読み込み完了時はキャッシュを破棄します。
- 禁則・英単語・幅不足は制約診断として記録します。制約が解決できない場合も原文は消しません。
- 高い数式では adaptive 行送りにより文字と数式の占有領域を含む高さを確保します。fixed は比較用です。
- JSON は原文・選択された方針・数式の配置座標・行の矩形・制約診断・各 run の矩形を保存します。

## 通常HTMLとの並列比較

ブラウザー独自のインラインレイアウトを対照群として、同じ原稿とMathJax数式を左右のプレビューへ表示します。HTML側の文字間隔は標準モードと、text-autospace / text-spacing-trim を試すモードを切り替えられます。CSS実装が異なる環境では対応状況を測定値に残します。JSONの nativeComparison にHTMLの文字を含む行数、式の寸法、オーバーフロー等を記録します。比較条件と解釈の注意点は [通常HTML + CSS + MathJax との並列比較](native-html-comparison.md) を参照。

## 確認手順

1. Node 24 を使用し、リポジトリで npm ci、続いて npm run dev を実行します。
2. http://127.0.0.1:5173/document.html を開きます。
3. 「混在・段落・空行」を開いた状態で「文字・数式の枠」「ベースライン」をオンにします。同じ TeX が二回出ても別の位置に描画されることを確認します。
4. 組版幅を 480 → 240 → 480 px と変え、原文と式の個数が同じであること、行数と数式の座標が変わることを確認します。
5. 「句読点と括弧の境界」で禁則再分割の有無を比較します。「10段落」で再配置を観察します。「T01–T07 組版衝突の比較」から各条件を選び、[衝突条件の検証マトリクス](collision-matrix.md)の判定範囲と照合します。
6. 「幅を超える数式」を選び、幅不足でも原文コピーが可能なことを確認します。
7. 不正な入力 \（x（実際には半角のバックスラッシュと開き括弧）を与え、閉じ記号不足と行・列が示され、前回の描画が残らないことを確認します。
8. JSON を保存し、原文・数式の ID と幾何情報を確認します。

[LuaLaTeX と jlreq の再実測・比較手順](latex-benchmark.md)、[数式境界アキの比較方針・自動診断](math-boundary-spacing.md) では、原文スペースと自動アキを別々に扱う T02 実験も確認できます。

## CI と未検証事項

GitHub Actions の node ジョブは Node 24 で npm test と構文検査を行います。browser ジョブは Chromium 上で複数 MathJax 数式、幅変更、誤入力後の復帰を確認し、2枚のスクリーンショットを artifact に保存します。

機械的な DOM 検査だけでは、フォント差・和文の空き・数式軸・可読性の検証はできません。とくに和文書体のフォールバックが異なる OS での目視比較と、七つの競合条件の網羅評価は今後の対象です。

このワークベンチは SVG に描画した文字・数式をそのまま選択可能な HTML の文章にはしていません。意味のあるコピー入力欄は別に保持しています。完全な読み上げ、MathML、編集可能な出力、印刷・PDF・EPUB の品質はまだ保証していません。
