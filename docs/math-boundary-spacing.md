# T02: 本文と数式の境界アキ（試験実装）

SUUSHIKI は数式内部の字間を MathJax に委ね、段落中の数式を非分割の項目として扱います。この検証では「本文に含まれる空白」と「組版による追加アキ」を混同しません。

## 選択可能な方針

- none（既定）：従来通り、原文が指定した空白のみを扱い、数式の外側に自動アキを追加しない。
- quarter：左右それぞれについて、隣接する本文が非空白であれば本文文字サイズの 1/4 を追加する。句読点や括弧の直前・直後にも加える比較用の単純な方式。
- contextual：隣接する本文の文字が文字・数字（漢字・ひらがな・カタカナや欧字・数字）なら 1/4 を追加し、句読点・括弧・記号・明示空白の直近では追加しない。これは選択可能な試験方針で、すべての数式・出版物に適用すべき規則ではない。

ここでの「1/4 em」は 0.25 × 本文 fontSize (CSS px) と定義します。MathJax の TeX 内側の空き、CSS による SVG 外余白、本文文字自身の字幅を同じ量として扱いません。

public/math-boundary.js は原文上の隣接文字から「生成候補」を求め、public/document-layout.js は行の先頭・末尾に移動した数式の候補を除外してから Stone で候補行を測り直します。数式の送り幅として「式本体 + 左の生成アキ + 右の生成アキ」を使い、数式そのものを描画するときは左アキを除いた矩形を使用します。禁則グループと幅条件は、追加アキを含む候補行に対して確認します。

原文の空白は元の文字 run のままで、生成アキは原文中に書き戻さず、数式の描画内容にも含めません。JSON の summary.geometry[].boundary は requestedLeft / requestedRight と appliedLeft / appliedRight（CSS px）を別に保存します。幅・本文サイズの変更ではこれらの値も再計算されます。

## 確認できること

- T02a：原文に空白なし。none / quarter / contextual の差が確認できる。
- T02b：原文に明示空白あり。自動アキで原文空白を二重にしない。
- T02c：句読点・括弧との隣接。quarter と contextual の意図的な差を観察できる。
- T03：幅が狭い行では追加アキを含めた組の禁則を検査し、行端の不要な生成アキを抑制する。
- TeX・式の識別子と出力 SVG の実測幅は、方針変更によって失われない。

## 未実装・比較上の注意

- これらは原文文字の種類に基づく候補規則であり、数式の意味や内部 TeX クラスから句読点の意味を推定しない。
- boundaryPolicy: stone は上流と比較するための候補表示モードで、行端の生成アキを再計算しない。行端での結果を検証するときは repair を選ぶ。
- 組版の行分割探索は既存の bounded greedy repair を使っている。選択した規則をすべての幅で満たす最適解の存在証明ではない。成立しない場合は診断を返す。
- 欧文の厳密な単語間空き、和欧間隔の出版規格差、MathJax SVG の外側に元々含まれる余白、均等配置による伸張、視覚的なアキの適切さは、この試験だけでは決められない。
- 原文・数式幅・幾何学的な重なりは自動検査できる。視覚的な調和の判定や読み上げには別の検証が必要。

既定の none は互換性のため維持します。試験比較を終えずに contextual を唯一の正解や既定値へ変更しません。
