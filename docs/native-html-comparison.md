# 通常HTML + CSS + MathJax と SUUSHIKI の並列比較

## 目的

SUUSHIKIの価値を、LaTeX組版に似た数値だけで判断しないための実験です。通常のブラウザーがすでに得意とすることと、独立した日本語＋数式組版が必要な場面を切り分けます。

原文と数式内容が同一の2系統を、/document.html に並べて表示します。

- SUUSHIKI: 既存の Stone + MathJax による測定、数式を非分割ボックスとした独自の改行・配置、禁則修復、内容対応行送り
- 通常HTML: 本文は span 内の素のテキストノード、数式は同じ測定時に生成した MathJax の mjx-container。改行はブラウザーのインラインレイアウトに委ねる
- LaTeX: 同じページの独立したLuaLaTeX + jlreq測定参照。PDFやTeXレイアウトをブラウザー内で描画した第三の列ではない

幅・フォント族・本文サイズ・TeXソース・MathJaxの生成結果を共有し、自然なインライン数式配置と独自の数式ボックス配置の差を観察します。一方、両列のレイアウト処理、和欧文の間隔、約物詰め、グリフのフォントメトリクス、数式外側のアキは同一になるよう強制していません。差はバグ・改善・仕様差のいずれでもあり得ます。

## モードと実装上の境界

「HTML側の文字間隔」で次の2つを選びます。

- 標準のHTML/CSS（調整なし）：text-autospace: no-autospace、text-spacing-trim: space-all を試み、明示的な付加調整を避ける。未対応ブラウザーでは宣言を無視する
- 最新CSSの実験：text-autospace: normal と text-spacing-trim: trim-start を指定。ブラウザーの CSS.supports と getComputedStyle を記録する。対応しても視覚的改善は保証しない

両列とも MathJax の行内数式の自動改行を無効にしています（現行SUUSHIKIの非分割数式契約を揃えるため）。MathJax 4が利用できる内部改行機能を否定するものではありません。将来「通常HTML＋数式内部改行あり」という第三の条件を独立に実験できます。

HTMLでは white-space: pre-wrap を使用し、原文の空白と明示改行を残します。SUUSHIKIの仮想段落分割・約物詰めと同じ結果になるとは仮定しません。HTMLのテキストはDOMテキストノードなので選択可能です。一方、SUUSHIKIの文面はSVGであり、原文は別のテキストエリアからコピーします。

## 実際に記録するもの

- 両者で共通：原文・数式出現数・MathJaxの元SVG
- HTML側：DOM Rangeが返した可視テキスト断片の位置と先頭・末尾、文字を含む行数、数式SVGの外接矩形、横はみ出し、実際の要素高、CSSサポートと計算後スタイル
- SUUSHIKI側：総行数、数式の配置座標、禁則と欧文単語の違反、各行の矩形、数式境界の生成アキ
- LaTeX側：参照環境の xkanjiskip と数式を含む文章の実測総幅・行数

JSONの nativeComparison と summary を比較できます。HTMLの textBearingLineCount は文字を含む行だけを数えるため、数式だけの行・空の明示改行は含まれず、SUUSHIKIの総行数と無条件には比較できません。DOM Rangeが返す文字片は、実際のグリフのインク領域を正確に表すものではありません。

サイズを狭くして数式が幅を超えた場合、SUUSHIKIは unsatisfied-width で表示を保留できますが、HTML側はブラウザーが描画を試みるので実際の横はみ出しを独立に観察できます。HTML側に違反が出たからといって即座にSUUSHIKIの品質が高いとはみなしません。スクロール、内部改行、縮小など、別のCSS/MathJax方針が有効な場合もあります。

## 観察するための具体的な手順

1. npm ci、npm run dev、http://127.0.0.1:5173/document.html を開く
2. T02a、T02cで数式との境界アキを none / contextual / elastic に切り替える。右列は原文とCSSモードだけで描画される
3. T03a、T03bの幅を連続的に変え、句読点・括弧の見え方とDOMの行断片を比較する
4. T04で分数の高さが本文の行送りにどう影響するかを観察する
5. T06aで数式単体が列幅を超える幅に狭め、SUUSHIKIの表示保留とHTMLのはみ出しを比較する
6. CSSモードをmodernに切り替える。指定したCSSのサポート状況を診断欄で確認
7. JSONを保存し、原文の保持、数式の同一性、行断片、オーバーフローを調べる

## 今後の判定に使うべきこと

- 現行ブラウザーで、どこまで問題が自然に解消するか
- 日本語約物と数式との境界について、どの条件なら独立した組版層が必要か
- 数式が高い場合の行送り、幅を越えた場合の処理を選択可能にする価値
- 使いやすさと性能の比較。現時点で高速性の優劣を示すベンチマークはない
- MathJaxの内部改行、CSSの均等割付、text-autospaceを加えた比較は別条件として続ける
