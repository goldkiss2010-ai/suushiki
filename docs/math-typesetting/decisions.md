# SUUSHIKI への適用：相違と未決事項

調査日：2026-10-10。この文書は [出典](sources.md) と [既存ルール](rules.md) を比較した設計上の提案であり、実装仕様の確定ではない。

## 資料間の相違

| 論点 | 資料から分かる相違 | SUUSHIKI で残す選択 |
| --- | --- | --- |
| 記号の空き | TeX の8要素分類、MathML の演算子辞書、JLREQ の文字クラスは対応する範囲が違う | 数式内部の組版方式と和文境界の方針を別々に記録 |
| ギリシャ大文字 | TeX 系と ISO 系の書体差がある | 文書の書体方針と著者の明示指定 |
| 定数・微分 | NIST の立体方針を、すべての TeX 原稿が採用するわけではない | 意味の分からない `d` や `e` は自動変換しない |
| 太字 | 太字立体・太字斜体などがある | 意味を含む入力の指定を保持 |
| 行内分数 | エンジンは積み上げ型を組めるが、『数学』にはスラッシュ型の出版方針がある | 著者・出版物による選択。自動置換は別機能 |
| 改行の記号位置 | TeX の既定候補は演算子後、JLREQ の別行式の助言は等号類の前を優先する | 前／後の方針。行内と別行を区別 |
| 改行候補の評価 | MathML 4 草案は候補の desirability を表せる。MathJax 4 行内は good/bad 評価を使わない | 必要な制御を実装側で確認 |
| 省略点・句読点・式番号 | 出版物固有の慣習がある | 一つの「正解」に固定せず文書単位で指定 |

## 第一段階で確認すること

既存の [architecture.md](../architecture.md) にある「分割しない数式ボックス」を採用する場合の提案。

1. **数式内部は数式エンジンに任せる。** S01 の間隔表を SUUSHIKI 側で重ねて適用しない。
2. **行を組む側は幅、上方寸法、下方寸法、ベースラインを受け取る。** 数学軸が取得可能なら独立した値として記録する。各値の単位、原点、余白を含むかも確認する。
3. **和文との接続は左右別々の問題として扱う。** 「和文＋式」「括弧＋式」「式＋句点」「式＋閉じ括弧」を比較する。式の先頭・末尾の見える字形だけで文法上の役割を決めない。
4. **境界の空きと原稿の空白は区別する。** 入力例中の ASCII 空白、ソース区間、組版が加えた空きを別に観察する。
5. **段落の改行を決定する主体を一つにする。** 第一段階で MathJax 4 を使う場合、公式文書の `linebreaks.inline: false` による非分割設定を候補として確認する。stone-engine.js でそのボックスを扱えることはまだ未確認。
6. **幅を超えた式の処理を決める。** 別行化、横スクロール、警告、縮小等の選択肢を比較する。文字幅の一部を切り捨てた状態を正常表示にしない。

これらは資料から得た設計上の提案であり、現在の両エンジンがこの契約を実装しているという主張ではない。

## 未解決の判断

| ID | 問い | 最初の確認方法 |
| --- | --- | --- |
| Q01 | 日本語本文のベースラインが取得できるか。数式とどの基準を合わせるか | C18 の文字・式を同じ行に置き、各エンジンの寸法定義を調べる |
| Q02 | 数式全体の外側に必要な空きをどう表現するか | C19–C23。普通の欧文 run との比較から始め、一般の数式へ一律拡張しない |
| Q03 | 句読点・括弧と式の間で、空きが二重に入るか | C20–C22。字形自身の余白、本文側の空き、式側の余白を記録 |
| Q04 | 高い式で行送りを増やすか、固定した行位置を維持するか | C13–C18。上下の描画範囲と隣接行との衝突を観察 |
| Q05 | 数式ボックスを行末から移動したとき、禁則と境界空きを再計算できるか | C21–C23。式幅付近で段落幅を少しずつ変える |
| Q06 | 将来、式を分割した後に単項・二項の空きや括弧サイズを保持できるか | C08・C26・C29。分割前後で式構造と再計測の必要性を調べる |
| Q07 | 数式用・日本語用フォントの組合せによる差はどれくらいか | 同じ入力を指定フォント組で比較。エンジン差との区別を記録 |
| Q08 | ソースの数式表記と文字選択・コピーを保持できるか | C04・C31。見た目、コピー結果、元ソースを比較 |
| Q09 | `d`、`e`、`i`、`max` 等の意味が不足する入力をどう扱うか | 既定表示を保持し、明示命令のある対照例と比較 |

## 優先順

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| 最初 | C18–C23：和文と式の基準・境界・折返し | 同じ入力を二つ以上の幅で再現し、寸法と空きの由来を説明できる |
| 次 | C01–C17：書体・内部配置・高い式 | 外部エンジンの既定動作、明示指定、フォント差を分けて説明できる |
| 後続 | C24–C32：出版方針、別行・複数行、意味・単位 | 機能ごとに採用方針と比較基準を決める |

最初の成果は「一段落の寸法と改行を説明できること」とする。資料の収集だけで、見た目の優劣や読みやすさを実証したとは判断しない。
