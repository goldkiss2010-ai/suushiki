# SUUSHIKI：Stone を保つための衝突整理

更新日：2026-10-10。[既存ルール](rules.md) の収集を踏まえ、選べる表記・慣習はパラメータへ回す。この文書では、同じ入力と設定で複数の制約を同時に満たせない場面、または二つの処理が同じ寸法・配置を調整して結果が崩れる場面を扱う。

Stone の確認範囲は [stone-engine.md](stone-engine.md) の固定コミット。**Stone の動作はソースで確認済み、数式を接続した衝突の発生は未実測**。下の対応案は SUUSHIKI の設計提案である。

## 選択を衝突と数えない

ギリシャ大文字、定数・微分記号、太字、分数の表記、句読点、省略点、式番号、フォントとサイズは、著者・文書の指定として残す。将来の式内改行で記号を前後どちらに置くかもパラメータ候補とする。意味が不明な `d`、`e`、`i`、複数文字の識別子を見た目だけで書き換えない。

既存の Stone オプションはそのまま引き継ぐ。新しい方針は、**数式の表記、本文との境界空き、行送りに収まらない場合、領域に収まらない場合**に分けて指定できる形を検討する。具体的なキー名・値・API はまだ確定しない。

パラメータの値を決めた後に、実際の寸法と制約を照合する。例えば積み上げ分数を選べることと、固定行送りで隣の行へ重ならずに置けることは別の条件である。

## 保持する前提

1. **本文の規則は Stone を基準とする。** `punctuationMode: "stone"`、`kinsoku: true`、`dividesByWords: true` などの既定を引き継ぎ、著者の既存指定も保つ。`justify` を指定した段落では、配分対象と対象外の考え方を保つ。
2. **数式内部は数式エンジンに担当させる。** Stone の文字種判定・約物詰め・均等配置を数式の内部に重ねない。数式を通常の文字列へ分解して配置し直さない。
3. **第一段階の数式は非分割ボックス。** 段落の折返しを決める側を一つにし、本文と式を同じ決定に参加させる。
4. **満たせない条件を記録する。** 禁則の無効化、式だけの無断縮小、分数表記の自動変更で成功扱いにしない。別行化などは明示した方針を選んだ場合に限る。

Stone の単語分割・禁則にも狭すぎる幅での例外がある。これを数式内部の分割へ自動的に拡張しない。

## 寸法と境界の契約

Stone の単位は CSS px、座標は y 下向き。数式の送り幅、基線から上・下の寸法、取得できれば数学軸をこの単位へ変換する。式の内部空き、外余白、インク範囲のどれを含む値かも記録する。基線が取得できるまでは外接矩形の中央を代用して合格としない。

左右の境界属性は、数式内部の TeX 要素クラスや見える先頭・末尾文字から自動的に決めない。本文の約物に対する扱い、境界の自然な空き、均等配分の可否、改行の可否を接続の契約として定める。和欧四分アキを選ぶ場合も、対象・約物との例外・行端での扱いをパラメータの定義に含める。

高さについて、行 i の最大下降寸法を D_i、次行の最大上昇寸法を A_(i+1)、基線間隔を L とすると、`D_i + A_(i+1) > L` は上下の占有領域が重なる候補になる。横方向の位置と実際のインク範囲も確認する。式の矩形を本文一文字の高さへ押し込めて衝突を隠さない。

## 次の小さな検証

まず T01–T03・T05 を、単純な式 `a+b=c` と一段落で確認する。**外部ボックスの接続、内部形状の維持、境界空き、禁則、一つの折返し決定**を説明できることを目標にする。次に T04・T06 の成立しない寸法を作り、満たせなかった制約を記録する。T07 は見た目だけの成功を防ぐ確認として同じ一段落に加える。

文書方針が違うだけの C05–C07・C24・C30・C32 などは衝突件数に数えない。既存の39ルール・32入力は出典の記録として残し、今回の検証対象をこの7パターンに絞る。
