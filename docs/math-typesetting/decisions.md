# SUUSHIKI：Stone の思想を継承する数式拡張・接続

更新日：2026-10-10。[既存ルール](rules.md) の収集を踏まえ、選べる表記・慣習はパラメータへ回す。この文書では、同じ入力と設定で複数の制約を同時に満たせない場面、または二つの処理が同じ寸法・配置を調整して結果が崩れる場面を扱う。

Stone の確認範囲は [stone-engine.md](stone-engine.md) の固定コミット。**この文書の作成時点では、Stone の動作をソースで確認済み、数式を接続した衝突の発生は未実測だった**。その後、T01–T07 の入力を実装し、原文・配置・寸法の限定的な自動検証を行った。検証状況は [衝突マトリクス](../collision-matrix.md) を参照。下の対応案は SUUSHIKI の設計提案である。

## 基本方針：思想を継承して拡張する

Stone から継承するのは、**日本語の細かな組版、画面サイズへの適応、内部配置を観察できること、実行速度への配慮**である。既存コード・API・文字単位のデータ構造・一定行送り・改行位置の維持は必須条件にしない。

数式を独立した組版要素として段落モデルへ加え、数式エンジンと計測・描画・ソース対応を接続する。公開 API の adapter、内部の拡張、必要な組版層の再構成を候補として比較する。方法は、数式と日本語が一つの行組版に参加できること、配置を説明できること、変更後の挙動と処理コストを観察できることから選ぶ。

上流と同じ結果を出すことは比較項目の一つとする。数式のための変更には、目的、採用したパラメータ、本文だけの場合への影響を記録する。実装の変更を衝突や不具合と数えるのは、選んだ要件を満たさない場合である。

## 選択を衝突と数えない

ギリシャ大文字、定数・微分記号、太字、分数の表記、句読点、省略点、式番号、フォントとサイズは、著者・文書の指定として残す。将来の式内改行で記号を前後どちらに置くかもパラメータ候補とする。意味が不明な `d`、`e`、`i`、複数文字の識別子を見た目だけで書き換えない。

既存の Stone オプションの意図は設定設計の出発点とするが、同じ API・既定値の維持は必須条件にしない。**数式の表記、本文との境界空き、行送りの決め方、領域に収まらない場合**を分けて指定できる形を検討する。具体的なキー名・値・API はまだ確定しない。

パラメータの値を決めた後に、実際の寸法と制約を照合する。例えば積み上げ分数を選べることと、固定行送りで隣の行へ重ならずに置けることは別の条件である。

## 拡張・接続の前提

1. **本文と数式の境界を定義する。** Stone の約物処理・禁則・単語の扱い・均等配置を参照し、数式を加えたときの規則を定める。本文だけの結果との差は観察し、意図した拡張と退行を区別する。
2. **数式内部は数式エンジンに担当させる。** Stone の文字種判定・約物詰め・均等配置を数式の内部に重ねない。数式を通常の文字列へ分解して配置し直さない。
3. **第一段階の数式は非分割ボックス。** 段落の折返しを決める側を一つにし、本文と式を同じ決定に参加させる。これは最初の検証範囲で、将来の式内改行を禁じるものではない。
4. **行送りを拡張できる。** 共通基線を持つ行に対し、固定行送りと内容の上下寸法に応じる行送りを方針として比較する。数式に応じた行送りの変更は通常の拡張候補として扱う。
5. **意味と寸法の一致を保つ。** 元ソースと数式の意味、計測値と描画の一致は接続の要件とする。表記変更・縮小・省略・別行化の適用は、選んだ方針として説明できるようにする。満たせなかった制約も記録する。

Stone の単語分割・禁則にも狭すぎる幅での例外がある。これを数式内部の分割へ自動的に拡張しない。

## 寸法と境界の契約

Stone の単位は CSS px、座標は y 下向き。数式の送り幅、基線から上・下の寸法、取得できれば数学軸をこの単位へ変換する。式の内部空き、外余白、インク範囲のどれを含む値かも記録する。基線が取得できるまでは外接矩形の中央を代用して合格としない。

左右の境界属性は、数式内部の TeX 要素クラスや見える先頭・末尾文字から自動的に決めない。本文の約物に対する扱い、境界の自然な空き、均等配分の可否、改行の可否を接続の契約として定める。和欧四分アキを選ぶ場合も、対象・約物との例外・行端での扱いをパラメータの定義に含める。

高さについて、行 i の最大下降寸法を D_i、次行の最大上昇寸法を A_(i+1)、基線間隔を L_i とすると、`D_i + A_(i+1) > L_i` は上下の占有領域が重なる候補になる。内容に応じる方針では、設定した最小行送りと必要な行間を加味して L_i を算出する。横方向の位置と実際のインク範囲も確認する。式の矩形を本文一文字の高さへ押し込めて衝突を隠さない。

## 次の小さな検証

最初の段階として T01–T03・T05 を、単純な式 `a+b=c` と一段落で確認する。**式項目の接続、内部形状の維持、境界空き、禁則、一つの折返し決定**を説明できることを目標にする。T04 では固定行送りと内容に応じる行送りを比較し、拡張による解消と残る制約を記録する。T06 は領域に収まらない条件を確認する。T07 は見た目だけの成功を防ぐ確認として同じ一段落に加える。

同じフォント・幅の本文のみの対照を作り、Stone との差と拡張後の挙動を観察する。元と同じ改行位置を必須の合格条件にせず、採用した規則との一致、ソース対応、再配置と計測のコストから判断する。

文書方針が違うだけの C05–C07・C24・C30・C32 などは衝突件数に数えない。既存の39ルール・32入力は出典の記録として残し、今回の検証対象をこの7パターンに絞る。
