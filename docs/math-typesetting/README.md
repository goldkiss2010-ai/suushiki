# 既存の数式組版ルール：調査入口

## 最初に押さえる点

1. **日本語の文字クラスと数式の要素クラスは区別する。** 全角の記号を扱う JLREQ の空きを、そのまま TeX 数式内部に加算しない。[S01・S09](sources.md)
2. **書体には複数の方針がある。** 例えばギリシャ大文字には TeX 系と ISO 系の違いがある。採用方針を指定できることが必要になる。[S04](sources.md)
3. **数学軸とベースラインは別の基準である。** 式の外接矩形を上下中央でそろえるだけでは、文字の基線を保持できない。[S05・S07](sources.md)
4. **仕様の存在と対応実装は別に確認する。** MathML 4 の改行規定からブラウザーの対応を推定しない。MathJax 4 の行内改行も、全体の行組版をどのエンジンが担当するか検討が必要である。[S06・S16](sources.md)

上の SUUSHIKI に関する判断は、資料を比較した設計上の提案である。

## 今回の範囲

別行数式、行列、式番号、数式内部の改行も収集対象に含めるが、既存の [research-plan.md](../research-plan.md) に従い、最初の実装対象は行内数式を含む一段落とする。縦書き、ページ組版、EPUB/Kindle は後続課題として維持する。

資料は全文転載せず、リンク、参照箇所、短い要約と独自の入力例を保存する。本文の該当箇所を確認した資料、検索取得部分のみ確認した資料、書誌だけ確認した規格を区別する。全資料を通読済みとする一覧ではない。
