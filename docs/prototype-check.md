# 単一数式の試作の一区切り

## 禁則の修正

既定の `boundaryPolicy: repair` は、元の Stone 候補に行頭・行末の禁則違反があるときだけ再分割する。`stone` は従来の候補をそのまま返す。

候補行を Stone で測定し、一時的な末尾改行で Stone 自身の行端処理を実行する。この実測例では、行頭括弧の半幅処理が改善に寄与した。その改行は入力・結果に加えない。禁則と横幅を満たし、後続も最後まで収まる分割を動的計画法で探す。元の文字・式の幅・書体・約物処理を保持し、見つかった行の位置だけ採用する。式は縮小・分割しない。

修正対象は空白・明示改行のない200書記素以下の短い段落に限定。範囲外は `repair.reason: unsupported-input` として従来の候補と診断を保持する。解が見つからなければ `no-fitting-partition`。これは本方式の測定・行分割で解がないという意味で、すべての組版方式で不可能だという証明ではない。欧文の単語内を保護する独立した規則は追加していない。

`repair.applied` と候補の試行数は JSON に記録する。修正できない候補を表示するか保留するかは `conflictPolicy` で選ぶ。固定行送りの縦の重なりは別の警告として残す。

## 再配置とコピー

幅・文字サイズ・和文フォントの変更で再計測する。更新中は保存・コピーを無効にし、連続操作では最後の状態まで再計算する。フォント読込完了も再計測の契機にしている。

コピーは構造化した原文から生成する。文章中の数式は `\(TeX\)`、数式だけなら TeX をクリップボードへ渡す。描画の置換文字や SVG のラベルは使わない。原文欄も表示し、書込みが拒否されたときは原文を選択して手動コピーできる。幅不足・表示保留でも原文を失わない。SVG の部分選択・MathML・数式の読み上げには未対応。

## 検証

Node の自動試験12件。修正前314幅の診断、修正後77幅の禁則・横幅・原文・式幅保持、幅不足時の原文からのコピー文字列を確認した。

Linux / Chromium 153.0.8010.0、和文フォールバック Noto Sans JP で、従来の寸法・位置・ベースライン８条件を再確認。句点・括弧を各46幅（計92条件）で試し、括弧の10条件を修正できた。20 px の式 `a+b=c` の例では、括弧の禁則を満たす幅が138 pxから128 pxに変わった。句点は118 px以上のまま。値はこの例と環境に依存する。

背の高い式を文字サイズ17/20/24 px、フォント指定 sans-serif/serif、幅160/480 pxの12条件で再配置し、占有領域の縦の重なりなし、SVG 寸法差0.05 px以内を確認した。和文のフォールバックが共通の場合もあるため、異なる書体すべての検証とは見なさない。

幅を連続で変更した後の最終状態、文章と LaTeX・式だけのクリップボード読み戻し、書込み拒否時の原文選択、幅不足からの復帰を確認。例外・ブラウザー警告・失敗リクエスト・外部通信はなし。

## 次の範囲

単一の式・横書き・左寄せ・高さ無制限の試作として区切る。複数数式、図表、長文、明示改行、欧文単語の分割方針、均等配置、数式内部の改行、完全なアクセシビリティ、全７衝突条件の統一試験は今後の範囲。Windows での今回の修正・コピーは利用者側の操作確認が残る。
