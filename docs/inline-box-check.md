# 仮ボックス接続の確認

実行計画の第４段階。Stone npm 0.2.0 の本体を変更せず、１つの非分割ボックスを横書き・左寄せの和文段落に参加させた。実際の数式の描画は次の段階。

## 接続方法

`public/inline-box.js` は、前の文章・ボックス・後の文章を別々の入力として保持する。Stone へ渡すテキストではボックスを１つの置換文字 U+FFFC とし、その１文字の送り幅だけを指定のボックス幅にする。行分割・禁則・約物処理は Stone に任せる。

行分割後に、置換文字の矩形をボックスの上下寸法に置き換える。「内容に合わせる」では行内の最大の上側・下側と行間からベースラインを配置し直す。「固定行送り」では Stone の行送りを保持する。表示する矩形は、この計算結果の座標と寸法をそのまま使う。

置換文字の字形は描かず、ボックスは別に描画する。原文とボックスの識別子を JSON に保持する。これは現行の文字モデルを利用した実験用アダプターで、任意のインライン要素を扱う最終 API ではない。

## 確認したこと

Linux / Node.js 24.19.0 / Chromium headless 153.0.8010.0、和文フォールバック Noto Sans JP。固定計測器による５件の自動試験と、実ブラウザーでの表示・操作・JSON 保存・画面確認を行った。

- 幅480 → 160 pxでボックスが丸ごと後ろの行に移り、幅104 pxを保持した。
- ボックスの上側39 px・下側49 px・高さ88 pxを、計算結果と描画に共通に使用した。
- 内容に合わせる場合、行の占有領域の重なりはなし。固定行送りの場合は重なりを検出した。隣接しない行に届く大きなボックスも検出対象。
- ボックス幅200 px / 組版幅160 pxでは、入力を保持して `unsatisfied-width` を返した。勝手に分割・縮小・省略しなかった。
- 置換文字の字形を描画せず、ボックス１個を描画した。文章の文字列とボックスの識別子を保持した。
- 最終のブラウザー確認で例外・警告・外部ホストへの通信・失敗したリクエストはなし。

「重なり」は行の占有領域の縦方向の交差で、字形のインク同士の衝突判定ではない。ボックスの寸法は CSS px の固定値で、和文の文字サイズの変更によって自動拡大しない。

## 制約と次の段階

１段落に１ボックス、横書き、左寄せ、高さ制限なし。数式の中の改行、均等配置、縮小、切り詰め、縦書きは対象外。数式直後の句読点等の境界条件は７つの衝突ケースとして別途検証する。置換文字により近傍の文字種判定が変わる可能性も、実際の数式への接続で観察する。

行ごとの占有領域の比較は小さい確認段落向けの実装で、速度の評価はまだ行っていない。コピー・読み上げの統合も未実装。
