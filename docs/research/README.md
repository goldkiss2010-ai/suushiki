## 用語と判断方法

- **行頭禁則／行末禁則**：日本語組版で、句点や終わり括弧を行頭に置かず、始め括弧を行末に置かない等の要件。出典は[W3C JLREQ日本語版](https://www.w3.org/TR/jlreq/)。
- **atomic inline（独立したインライン要素）**：普通の文字列とは異なる改行機会を持つ置換要素やインラインブロック等。出典は[CSS Text Level 3](https://www.w3.org/TR/css-text-3/#line-breaking)。MathJaxそのものが日本語禁則を壊したとは、この結果だけではいえない。
- **禁則プローブ**：Stoneの文字集合で行頭・行末の文字を機械的に分類する判定。JLREQ全要件の自動適合試験ではない。
- **composed**：当該実験器具の制約・幅チェックが満たされた状態。視覚品質、印刷品質、ブラウザー間互換、アクセシビリティの保証ではない。
- **Stone候補**：Stoneによる改行候補をSUUSHIKIの数式測定アダプター経由で使用した対照。**Stone単体の動作ではない**。
- **既存方式の方が有利な場合も記録する**：SUUSHIKIの利点だけを採録しない。反例、修復不能、幅不足も同じ優先度で残す。

## 維持方針

追加の記録は既存IDに紐づけ、次の順序で記します：**問い／出典／原文・表示幅・環境／比較条件／観測／解釈／未確認／再現方法**。実測のない期待や技術的な提案を「結果」に混ぜません。数値が変わったら以前の条件と日付も残します。

現段階では新しい衝突パターンを探しません。既存の観測値を整え、文献の対応箇所・発生条件・再現方法を明瞭にすることを優先します。
