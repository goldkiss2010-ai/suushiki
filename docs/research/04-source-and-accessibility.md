# 数式の見た目と原文の対応：TeX、SVG、選択、読み上げ

**検索語**：数式のコピー／MathJax SVGコピー／日本語本文の選択／原文保持／TeXソース／アクセシビリティ／MathML／スクリーンリーダー／読み上げ／数式の意味。

対象：K07/T07、およびK01・K05・K06の原文保護に関する部分。

## 1. 「描画された」と「意味を取り出せる」は別の条件

MathJaxのSVGモードは、数式字形をベクター形状として配置する方式です。公式資料は、SVGを画像として保存できる一方、字形がパスに変換されるため一般のテキストのようにそのままコピー・貼り付けできないと説明しています。

- [MathJax 4 SVG Support（公式）](https://docs.mathjax.org/en/latest/output/svg.html)

日本語本文までSVGへ変換する場合、視覚的に表示できても、段落を普通のHTMLテキストのように選択・コピーしたり、読み上げさせたりする条件は満たせない可能性があります。

## 2. SUUSHIKIが確認した機械的な対応（T07）

T07の原稿：

    実数\(\mathbb{R}\)上で\(f(x)\)を考える。

SUUSHIKIの文書ワークベンチは、TeXの原稿を構文解析するとき、各式の開始・終了位置と出現ごとのIDを保持します。同じTeX文字列が複数回現れた場合でも、異なる場所の式として扱います。

現行の検証には次の経路があります。

- 原文全文を別のtextareaからコピーする。
- 原文中の全数式TeXを取り出し、コピーする。
- 原文・数式出現・描画座標・測定寸法をJSONへ記録する。
- 構文が不正（数式の区切りが閉じない等）の場合、誤った前回描画を残さず、原文を保持した状態でエラーを表示する。

ブラウザーに描画された全文章を選択できることは、これらの機能では代替できません。実験的なSUUSHIKI側の表示はSVG中心であり、コピー元となる意味表現は別欄に保持されています。一方、比較用の通常HTML側は、本文のテキストをDOMテキストノードとして保持しているため、少なくとも本文をブラウザーの標準の選択操作で扱えます。

## 3. 既知の区別と未確認事項

| 確認対象 | 現状 |
| --- | --- |
| TeXの原文を保存 | 動作確認あり |
| 式の開始・終了位置、出現IDと計測位置の対応 | 自動テストあり |
| 原文全文・数式TeXのコピー経路 | UIとブラウザーテストあり |
| SUUSHIKIが描画した日本語本文の直接範囲選択 | 未対応 |
| 文の途中にある数式を含めた一続きの選択・コピー | 未検証 |
| TeXからMathML等へのアクセシブルな出力経路 | 未実装・未検証 |
| スクリーンリーダーによる日本語と数式の読み上げ | **未検証** |
| PDF／EPUBの意味保持と読み上げ | **対象外** |

**解釈上の注意**：MathJax本体には、表示形式やアクセシビリティに関わる独立した機能があります。SUUSHIKIの現行の簡易構成でそれらを無効・未実装にしていることを、MathJax全体の機能不足と評価しません。

## 4. この記録の結論

T07で確認できたのは、**見た目だけのSVGに閉じず、元の数式ソースと配置の対応を保存できる**ことです。それは、視覚的な組版と意味上の文書処理を分離する際の基本条件です。

ただし、読み上げ、アクセシブルな数式、任意の範囲選択まで解決したという実測はありません。

この問題を新しい組版エンジンを作る理由へ直結させず、既存HTML／MathML／MathJaxの持つ意味表現と、現行SUUSHIKIの表現形式の差として記録します。
