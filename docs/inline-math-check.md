# 実際の数式への接続

実行計画の第５段階。第４段階の仮ボックスの寸法を MathJax の表示結果から取得し、矩形を実際の数式へ置き換えた。

## 実装

- 単体表示の４式から１つを選び、表示された SVG の幅・ベースライン上側・下側を取得する。計算には丸め前の CSS px を使い、画面の数値だけを丸める。
- 同じ寸法を Stone の送り幅と行の占有領域へ渡し、和文と共通の行分割を行う。行内の式は分割しない。
- 配置後は和文の SVG と MathJax のルート SVG を同じ段落領域に置く。式の SVG は計算された x / y / 幅 / 高さで絶対配置する。
- MathJax の `fontCache: 'none'` による自己完結したパス出力を使い、原式と式の識別子を別に保持する。
- 各行のベースライン間隔、行の占有領域の重なり、配置後の表示寸法との差を表示・JSON 保存する。

数式を別の SVG の中にネストすると、その `getBoundingClientRect()` はルート SVG のビューポートと異なる内容の境界を返す。そのため、この段階ではルート SVG のまま配置し、測定時と配置時に同じ矩形の定義を使う。単一 SVG への書き出しは未実装。

## 確認

Linux / Node.js 24.19.0 / Chromium headless 153.0.8010.0。和文フォールバックは Noto Sans JP。第４段階の５件の自動試験を維持し、実ブラウザーで４式の挿入、折り返し、サイズ変更、行送り切り替え、JSON 保存を確認した。Windows での第５段階の操作は未確認。

幅160 px / 文字サイズ20 px、内容に合わせる配置：

| 式 | 表示幅 | 表示高さ | 測定した幅・高さとの差 | 行の占有領域の重なり |
| --- | ---: | ---: | --- | --- |
| `f(x)=x^2` | 105.016 | 26.766 | いずれも0 | なし |
| `\frac{1}{1+x^2}` | 50.891 | 32.188 | いずれも0 | なし |
| `\dfrac{\sum_{k=1}^{n} k^2}{1+\dfrac{1}{x}}` | 98.359 | 88.734 | いずれも0 | なし |
| `x\in\mathbb{R}` | 62.266 | 18.000 | いずれも0 | なし |

単位は CSS px、表示値は小数第３位まで。幅480 pxと160 pxの計８条件で、計算した x / y と表示位置の差は0.05 px以内だった。SVG 座標原点から得た数式のベースラインと配置ベースラインの差は0.023 px未満だった。`f(x)=x^2` は幅480 pxで１行目、160 pxで３行目へ丸ごと移った。文字サイズ24 pxへの変更で式の寸法が増え、再配置できた。最終確認でブラウザーの例外・警告・外部通信・失敗リクエストはなし。

背の高い式の前後のベースライン間隔は約53.666 px・79.069 px、ほかの通常の行は32 px。固定行送りではすべて32 pxとなり、行の占有領域が３組重なった。行送りを一律に拡大する実装ではないため、小さな式や通常の文章の行では見た目の変化が小さい。
